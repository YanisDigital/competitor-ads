# meta-ads-niche-report

Скилл для Claude, который собирает активную рекламу конкурентов из
**Библиотеки рекламы Meta** (Facebook/Instagram) и превращает её в отчёт и
набор готовых к тесту гипотез объявлений для таргетолога. Подходит для
локального бизнеса (ниша + город) и для онлайн-ниш (дропшиппинг на США,
курсы). Без платных API.

English version: [README.md](README.md)

## Где это работает (прочитай сначала)

> **Одной загрузки zip в claude.ai недостаточно.** Установка скилла ничего
> больше не ставит, а обычный чат не может открыть facebook.com. Выбери
> вариант под то, как ты пользуешься Claude.

Скилл читает Библиотеку рекламы на facebook.com. Meta отдаёт её только
настоящему браузеру в обычной сети (из облачных контейнеров приходит 403).
Поэтому важно, где работает Claude и каким браузером он может управлять:

| Где ты работаешь | Работает? | Что нужно настроить |
|---|---|---|
| **Claude Code** (терминал) или **вкладка Code десктопного приложения** | Да, всё: сбор, проверка сайтов, сравнение, инструменты гипотез, Excel/HTML | Один раз поставить: Python 3.10+, `pip install playwright`, `python -m playwright install chromium`, Node.js (и `pip install openpyxl` для Excel). Claude спросит перед установкой |
| **Вкладка Code или Cowork со встроенным браузером** | Сбор в браузерном режиме | Для самого браузера ничего. Скриптам (отчёт, экспорт) всё равно нужен Node.js |
| **Чат в claude.ai или десктопном приложении с подключённым расширением Claude in Chrome** | Только сбор и отчёт в браузерном режиме | Установить расширение **Claude in Chrome**, войти в *тот же* аккаунт, убедиться, что браузер показан как подключённый. В чате нет файлов и команд: нет папок срезов, проверки сайтов, сравнения и экспорта |
| **Чат без инструмента браузера** (claude.ai или вкладка чата приложения, без расширения) | **Нет.** Из своей песочницы Claude не достаёт до facebook.com, скилл останавливается и говорит об этом | Использовать вкладку Code или подключить расширение |

Если чат отвечает, что браузер не подключён, скилл исправен: нет самого
подключения. Перейди во вкладку Code или поправь расширение (установлено,
включено, тот же аккаунт, Chrome перезапущен).

## Что получаешь

- **Кто рекламируется**, сколько объявлений, как давно, куда ведёт реклама
  (Директ/Messenger, профиль Instagram, сайт, маркетплейс, установка
  приложения, WhatsApp, Telegram, Telegram-бот, партнёрская ссылка).
- **Какие офферы и хуки повторяются**: скидки, бесплатная доставка, бонус,
  персонализация, гарантия, срочность и др., плюс хуки под нишу из пресетов.
  Цены и типичные скидки (в грн или $).
- **Долгожители**, ранжированные по числу вариантов креатива (много вариантов
  одного объявления обычно значит активный тест), со ссылками на креативы.
- **Сети страниц**: один текст объявления на разных страницах и несколько
  страниц, ведущих на один магазин.
- **Пометки шума**: локальные магазины, крупные платформы (Amazon, eBay,
  реклама установки приложений), курсы/школы, чтобы они не искажали выводы.
- **Проверка сайтов лидеров**: цены, хуки, признак Shopify, скриншот и то, что
  реклама обещает, а страница не показывает.
- **Гипотезы объявлений** с доказательствами по рекламодателям, брифом клиента
  (гипотезы обещают только то, что клиент может выполнить), автопроверкой
  текстов, приоритизированным планом теста и гипотезами из того, что
  изменилось между срезами.
- **Мониторинг**: сравнение двух срезов (новые, остановленные, масштабирующиеся
  объявления).
- **Excel** и **HTML-отчёт одним файлом**, чтобы делиться.

[examples/sample-report.md](examples/sample-report.md) — полный пример отчёта
(вымышленные данные) в формате из 8 разделов, который выдаёт скилл.

## Быстрый старт

1. Установи скилл (ниже).
2. Напиши Claude обычными словами, например: «проанализируй рекламу
   конкурентов: салоны красоты в Одессе», «сделай срез по дропшиппингу на
   США», затем «проверь сайты лидеров» и «напиши гипотезы объявлений для
   моего клиента».
3. Через неделю-две: «сделай новый срез и сравни с прошлым».
4. Чтобы поделиться: «сохрани в Excel» или «сделай HTML-отчёт».

Терминал не нужен: команды запускает Claude. Для этого нужны Claude Code или
**вкладка Code десктопного приложения** (доступ к файлам и командам). В
обычном чате работает только отчёт в браузерном режиме, и только с
подключённым браузером (см. [Где это работает](#где-это-работает-прочитай-сначала));
срезы, проверка сайтов, сравнение, инструменты гипотез и экспорт требуют
вкладку Code.

## Как это работает

Библиотека рекламы (`facebook.com/ads/library`) открывается без логина.
Объявления приходят двумя путями: JSON, встроенный в страницу при первой
загрузке, и ответы `graphql` при прокрутке или новом поиске.
[`scripts/collector.js`](plugins/meta-ads-niche-report/skills/meta-ads-niche-report/scripts/collector.js)
перехватывает оба пути на стороне клиента. Это единственный источник логики
сбора и анализа, все остальные скрипты вызывают его.

Два режима сбора, выбираются автоматически:

1. **Браузерный режим**: инструмент браузера в сессии Claude (встроенный
   браузер Cowork, Claude in Chrome, браузер десктопного приложения)
   управляет Библиотекой. См.
   [references/browser-mode.md](plugins/meta-ads-niche-report/skills/meta-ads-niche-report/references/browser-mode.md).
2. **CLI-режим**: [`scripts/scrape.py`](plugins/meta-ads-niche-report/skills/meta-ads-niche-report/scripts/scrape.py)
   управляет настоящим Chromium через Playwright и сохраняет срез с датой в
   `out/<пресет>/<дата>/`.

Из облачных контейнеров `facebook.com` отдаёт `403`: работает только из
среды с обычным, не датацентровым сетевым путём (твоя машина или сессия с
настоящим инструментом браузера).

## Порядок работы и файлы

Всё по одному срезу лежит в `out/<пресет>/<дата>/` (не попадает в git и не
публикуется). Каждый шаг читает то, что записали предыдущие:

| Шаг | Что говоришь | Скрипт | Что записывает |
|---|---|---|---|
| Сбор | «сделай срез по ...» | `scrape.py` | `ads.csv`, `report.json`, `run.json` |
| Сайты лидеров | «проверь сайты лидеров» | `check_sites.py` | `sites.json`, `sites/*.png` |
| Бриф клиента | (Claude задаёт до 5 вопросов) | `client_fit.js` | `client.json` (в папке среза или уровнем выше) |
| Гипотезы | «напиши гипотезы объявлений» | Claude | `hypotheses.json` |
| Проверка текстов | (автоматически) | `lint_hypotheses.js` | `hypotheses_lint.json` |
| Приоритеты и план | (автоматически) | `plan_tests.js` | `test_plan.json` |
| Сравнение с прошлым срезом | «сравни с прошлым» | `compare.js` | `diff.json` (в более новой папке) |
| Поделиться | «сохрани в Excel» / «сделай HTML-отчёт» | `export_xlsx.py` / `export_html.js` | `report.xlsx` / `report.html` |

| Скрипт | Что нужно |
|---|---|
| `scrape.py`, `check_sites.py` | Python 3.10+, Playwright, а для `check_sites.py` ещё Node.js |
| `compare.js`, `client_fit.js`, `lint_hypotheses.js`, `plan_tests.js`, `export_html.js` | Node.js |
| `export_xlsx.py` | Python, `openpyxl`, Node.js |

## Пресеты ниш

В [`presets/`](plugins/meta-ads-niche-report/skills/meta-ads-niche-report/presets)
лежат готовые запросы (услуги × языки), хуки под нишу и слова-шум. В Claude
пресет подбирается автоматически, если ниша совпадает, и скилл сообщает, какой
использовал. Если ниши в списке нет, запросы он составит сам.

| Ниша | id пресета | Примечания |
|---|---|---|
| Салоны красоты, маникюр, брови, ресницы | `beauty` | укр/рус, нужен город |
| Стоматологии | `dentistry` | укр/рус, нужен город |
| Залы, фитнес-студии, тренеры | `fitness` | укр/рус, нужен город |
| Автосервис, шиномонтаж, детейлинг | `auto-service` | укр/рус, нужен город |
| Дропшиппинг / Shopify-магазины на США | `ecom-dropship-us` | английский, страна US, цены в $, без города, запросы по товарам |
| Онлайн-курсы: таргет, SMM, маркетинг | `infobiz-marketing` | укр/рус, без города |
| Курсы для бьюти-мастеров | `infobiz-beauty` | укр/рус, без города |
| Крафтовое пиво (пивоварни, магазины), Украина | `craft-beer-ua` | укр, без города; широкие запросы («на розлив», «в подарунок») дают шум, рекламодателей проверять вручную |

CLI: `python scrape.py --preset beauty --city-uk Одеса --city-ru Одесса`
(`--express` — быстрый срез из 3 запросов, `--max-queries`, `--list-presets`,
`--exact` — поиск точной фразы: меньше шума, но и конкурентов находится меньше).
Чтобы добавить нишу, скопируй любой пресет, поменяй `id`, `services`,
`extra_hooks`, `noise` и положи в ту же папку. В пресете можно также задать
`country`, `currency`, `base_hooks` и `online_only` (убирает локальные
магазины и крупные платформы из списка долгожителей).

## Проверка сайтов лидеров

`check_sites.py <срез> --top 5` открывает посадочную страницу, на которую
реально ведёт реклама топ-рекламодателей, и записывает заголовок,
подзаголовки, цены, хуки (бесплатная доставка, гарантия и т.д.), признак
Shopify (по ресурсам страницы, поэтому работает и на своих доменах),
скриншот первого экрана. Затем страница сравнивается с рекламой: что реклама
обещает, а на странице не видно; что есть на странице, но в рекламе не
упомянуто; цены из рекламы, которых нет на странице. Расхождение — зацепка, а
не доказательство (баннеры и всплывающие окна могут не попасть в текст
страницы). Сайты с защитой от ботов пропускаются, обход не делается; не
больше 10 сайтов за запуск.

## Гипотезы объявлений

Раздел гипотез устроен так, чтобы не преувеличивать выводы:

- **Доказательства по рекламодателям.** Хук считается по рекламодателям, а не
  по объявлениям, страницы с общим сайтом объединяются в одного. У каждого
  хука есть сила сигнала (`strong`: 5+ рекламодателей и никто не даёт больше
  50%; `moderate`; `weak`: один-два рекламодателя, то есть привычка одного
  конкурента, а не тренд ниши), пометка круговости (слова хука входят в твои же
  поисковые запросы) и примеры объявлений со ссылками.
- **Бриф клиента.** Перед написанием Claude задаёт до 5 коротких вопросов
  (товар и цена, гарантия, отзывы и можно ли их цитировать, бонус/комплекты/
  бесплатная доставка, копии на рынке, реальные дедлайны) и сохраняет
  `client.json` (шаблон:
  [client.example.json](plugins/meta-ads-niche-report/skills/meta-ads-niche-report/client.example.json);
  `null` — ещё не спрашивали, `false`/`0` — этого нет). `client_fit.js`
  разделяет хуки на доступные, заблокированные (клиент сказал, что этого нет)
  и «нужно уточнить»; гипотезы используют подтверждённые факты дословно вместо
  плейсхолдеров.
- **Автопроверка текстов** (`lint_hypotheses.js`): обязательные поля, длина
  заголовка (~40 символов), ~125 символов, видимых до «Ещё», незаполненные
  плейсхолдеры, рискованные формулировки (личные характеристики зрителя,
  медицинские и абсолютные обещания, «до/после», превосходная степень, капс,
  ложная срочность) и, с `client.json`, обещания, которые клиент не
  подтверждал (дни гарантии, оценка, число отзывов, скидка, цены, хуки,
  которые клиент отрицал). Это эвристики, а не проверка Meta: рекламу одобряет
  сама Meta, и её правила меняются.
- **Приоритизация и план теста** (`plan_tests.js`): балл = сила сигнала ×
  готовность / трудоёмкость (готовность берётся из брифа клиента; ошибки в
  тексте режут её вдвое). Тесты идут раундами по 2 с разными типами переменной
  (креатив, оффер, посадочная, аудитория); если в `client.json` есть
  `target_cpa`, у раунда появляется бюджет (2 варианта × 50 событий
  оптимизации × CPA, ориентир). Балл упорядочивает работу и не предсказывает
  результат.
- **Гипотезы из динамики.** При двух срезах в `diff.json` есть блок
  `dynamics`: хуки объявлений с ростом числа вариантов (что конкуренты
  масштабируют), хуки, которых больше среди пропавших молодых тестов (только
  из уверенных остановок и при достаточном объёме данных), что несут новые
  рекламодатели и как сместилась доля форматов.

## Чистка рекламодателей и оценка запросов

Библиотека ищет по **тексту** объявления, поэтому в выдачу попадают не
конкуренты (баня, где упомянуто пиво, магазины бокалов, организаторы
фестивалей). Скилл просит Claude прочитать рекламодателей и сохраняет решение
в `curation.json` рядом с `ads.csv`:

```json
{ "include": { "Brewery A": "Производитель", "Shop B": "Магазин пива" },
  "exclude": ["Название страницы"], "notes": "кого убрали и почему" }
```

`include` это белый список (значения станут колонкой «Тип»), `exclude` чёрный.
Отчёт, Excel и HTML строятся только по оставленным рекламодателям; без файла
ничего не меняется. Отчёт также показывает **по каждому запросу**, сколько
объявлений и рекламодателей он нашёл и сколько из них настоящие конкуренты, и
отказала ли Meta в подгрузке (лист «Запросы» в Excel и раздел в HTML), чтобы
слабые запросы можно было заменить.

## Ссылки на картинку и видео

В `ads.csv` и на листе объявлений в Excel есть ссылки на сам креатив:
картинка в полном размере (для видео кадр-превью) и видео в HD (иначе SD),
колонки «Картинка» и «Видео» с гиперссылками. Meta отдаёт их со своего CDN с
подписанным адресом, который перестаёт работать через какое-то время (обычно
дни), поэтому нужное открывайте или скачивайте сразу; постоянная ссылка это
ссылка на само объявление в Библиотеке. Сохраняются только ссылки http(s).

## Остановленные объявления и период показа

`scrape.py --status all` (или `inactive`) собирает и объявления, которые
Библиотека больше не показывает как активные; `--date-from` и `--date-to`
(ГГГГ-ММ-ДД) ограничивают период, в который объявления показывались (не день
старта). Остановленные объявления показывают, что конкурент пробовал и
выключил: в отчёте они в отдельном блоке (сколько дней показывались, сколько
остановлено меньше чем за 2 недели, самые долгие; лист «Остановленные» в Excel
и раздел в HTML), а возраст и долгожители считаются только по работающим.
Долгий показ до остановки не доказывает, что объявление работало.

Другие фильтры: `--language uk ru` (язык текста объявления), `--media
video|image|meme` (чистое «image» Библиотека не отдаёт, поэтому `image`
отправляется как картинки и мемы) и `--sort relevancy` (вместо порядка по
охвату: другая верхушка выдачи, тот же лимит ~30 объявлений на запрос).
Фильтры сужают выдачу, поэтому такой срез не стоит сравнивать с обычным.

## Все объявления конкурентов

Поиск по словам видит только объявления, совпавшие с запросом. Когда конкуренты
записаны в `curation.json`, `scrape.py --pages-of <срез> --out <новая папка>`
собирает все их активные объявления (до 15 страниц; страна берётся из
`run.json` среза). Нужен срез версии 0.12.4 или новее: в нём есть колонка
`page_id`. На крафтовом пиве у одной пивоварни это дало 11 объявлений вместо 3,
у другой 9 вместо 2. Новые поля объявления с 0.12.4: размер страницы
рекламодателя, подпись ссылки, тип кнопки без перевода, пометка Meta «создано
ИИ» и ссылка на профиль.

## Предупреждения и гигиена запросов

В отчёте есть блок **«Предупреждения»** (сводка Excel, начало HTML): малая
выборка (меньше 10 рекламодателей: выводы это гипотезы, а не тренд ниши),
запросы, по которым Meta отказала в подгрузке, запросы без результатов,
**сезон** из пресета (Октоберфест, 8 марта, чёрная пятница: часть рекламы
временная) и заметка о **правилах** для ограниченных ниш (алкоголь,
медицина, вес, обещание дохода). В пресете это поля `seasons` (`from`/`to` как
`ММ-ДД`) и `policy`.

После чистки `node scripts/suggest_queries.js <срез>` оставляет только запросы,
нашедшие хотя бы одного конкурента, объясняет каждый убранный и печатает
готовый список `services` для пресета.

## Мониторинг: сравнение двух срезов

Запусти один пресет дважды с интервалом в неделю-две (каждый запуск попадает
в свою папку с датой), затем попроси Claude сравнить, либо выполни
`node .../scripts/compare.js out/<пресет>` (с одной папкой сравниваются два
последних среза внутри неё; `compare.js out/a out/b` сравнивает два
конкретных). Результат — `diff.json` в более новой папке: новые объявления,
остановленные, доля пропавших молодых тестов (<30 дней), объявления с ростом
числа вариантов креатива (масштабирование), страницы, которые появились,
исчезли или выросли.

Библиотека показывает только верх выдачи (около 120 объявлений на запрос),
поэтому пропавшее во втором срезе объявление могло просто выпасть из топа.
Остановка считается уверенной, только если её запрос перезапущен и вернул
меньше 90 объявлений.

## Поделиться: Excel и HTML

- **Excel** (`export_xlsx.py`): `report.xlsx` со сводкой (формулы), всеми
  объявлениями со ссылками на креативы, всеми рекламодателями (флаги
  локальный/платформа, общие сайты), долгожителями, сетями страниц и, при
  наличии данных, листами изменений, гипотез (с колонкой автопроверки) и плана
  тестов.
- **HTML** (`export_html.js`): `report.html`, один самодостаточный файл без
  внешних файлов, шрифтов и скриптов (диаграммы на чистом CSS, скриншоты
  встроены), который открывается где угодно, в том числе на телефоне, и
  печатается. В нём сводка, диаграммы, рекламодатели, долгожители, сети страниц
  и, при наличии данных, проверка сайтов, гипотезы с планом теста и изменения.
  `client.json` в отчёт не попадает. Строгая Content-Security-Policy
  запрещает всё, кроме собственных встроенных стилей, а весь текст объявлений
  экранируется, поэтому вредоносное объявление ничего не внедрит.

## Требования

- **Браузерный режим**: инструмент браузера, *подключённый* к сессии Claude:
  встроенный браузер десктопного приложения / Cowork (ставить ничего не
  нужно) или расширение Claude in Chrome (установить и войти в тот же
  аккаунт). Обычный чат без того и другого собирать не может.
- **CLI-режим и проверка сайтов**: Python 3.10+ и [Playwright](https://playwright.dev/python/):
  ```bash
  pip install playwright
  python -m playwright install chromium
  ```
- **Всё остальное**: Node.js; для экспорта в Excel ещё `pip install openpyxl`.

Скилл и тесты ничего не устанавливают сами: ты (или Claude с твоего
согласия) ставишь это, когда реально нужно.

## Ограничения

- Анализируется только **текст** объявления (заголовок, тело, CTA, ссылка), а
  не картинки и видео креатива.
- Отчёт — **снимок на момент запуска**, а библиотека отдаёт около 120
  объявлений на запрос (верх по охвату), а не весь рынок.
- Вне ЕС Meta не показывает бюджет и охват коммерческой рекламы, поэтому
  «сила» рекламодателя видна косвенно: по числу объявлений, возрасту и числу
  вариантов креатива.
- Поиск ищет по **тексту** объявления, а не по гео рекламодателя: город должен
  быть в самом объявлении, чтобы попасть в выборку по запросу с городом.
- Дропшиппинг по данным не отличить от обычного небольшого бренда: скилл
  сужает список кандидатов, а решаешь ты после просмотра креативов и сайтов.
  Определение локальных магазинов и платформ эвристическое.
- Частоты хуков — это совпадения регулярных выражений с текстом. Хуки, которые
  есть у одного-двух рекламодателей, помечены `weak` и не являются трендом
  ниши; каждую гипотезу читай как тест, а не как вывод.
- Для сравнения срезов нужны одни и те же запросы, а малые выборки делают
  сигнал «проваленный тест» слабым.
- Автопроверка текстов гипотез и балл плана теста — эвристики.
